# 切割轮系列化实战验证计划 V1

日期：2026-10-06。目标是验证已存在的局内强化能否共用一套切割轮视觉语言；不定义正式武器等级，不改变伤害、范围、碰撞或卡池。

## 对照样本

在真实战斗快照的基础上，只改表现输入，按 320 与 390 像素宽各看五种状态：基础；加长支架；加长支架＋联动刀盘；强化齿刃；强化齿刃＋高速传动。再看两条路线兼修，验证结构不会互相覆盖。基础蓝刀盘固定，强化齿刃对比旧灰钢图与六辐蓝漆候选。

## 判定

1. 30～35px 刀盘尺寸下：基础与齿刃强化在外齿／辐条结构上能区分，且蓝漆、露钢、轮廓像同一产品家族。
2. 支架、前后刀盘、高速旋转分别有可见变化；兼修仍能读清各项变化，不出现重叠误读或数量角标。
3. 动静态都检查；图片解码、透明边界、控制台错误和测试快照不变性分别记录。截图通过不等于运动体感通过。
4. 候选失败就保留旧默认，不通过改玩法参数补救；候选通过才考虑替换默认图。

## 执行顺序

先做候选图的可切换表现引用及自动对照，再用网页标准客户端核查实际战斗与两宽截图；最后记录 PASS／FAIL／未验证，更新主线恢复点。微信真机和玩家动态审美单列未验证。

## 本轮结果

执行 `station-prototype/verify-saw-family.cjs`，从真实战斗快照渲染两宽各 9 组状态，截图在 `output/saw-family-*.png`。候选只由表现输入 `advancedSawArt='blue'` 选择，真实游戏默认仍用旧灰钢版。候选来源为内置图像生成编辑：以原高级六辐刀盘为形状目标、基础蓝刀盘为材质参考；保留原图和候选，未替换。

|检查|结果|依据|
|---|---|---|
|基础与加长支架|PASS|两宽截图中刀盘的左右覆盖尺寸有明显变化；未改规则半径|
|强化齿刃蓝色候选的家族材质|部分接近|与蓝车体和基础蓝盘同色系，灰钢外齿保留|
|强化齿刃蓝色候选的级差识别|FAIL|旋转色带遮住大部分六辐；约 30px 下与基础蓝盘过于相似，不能作为默认替换|
|联动刀盘的新增结构识别|FAIL|起手已有两件刀盘、前后四轮；联动线虽输出，截图中几乎不可辨，玩家看不出升级前后差异|
|高速传动静帧识别|不适用|高速是运动状态；现有速度数值断言通过，动态体感本轮未做真人审核|
|两路线兼修|技术 PASS／视觉未通过|320/390 无重叠崩坏或页面错误，但继承上述级差与联动读感问题|
|资源解码、快照不变、既有流程|PASS|两宽 9 状态测试、`verify-saw-slots`、`verify-full-expedition` 三段胜负重开、标准网页客户端与截图|
|微信真机、图集安全边、玩家动感|未验证|候选底缘安全边约 8px，尚未规范化|

结论：**不替换默认高级刀盘，也不批量生成更多“等级图”**。下一次先在结构表现层解决“强化齿刃轮廓差异被色带遮盖”和“联动升级与既有两件装备混淆”，再重新做两宽动静态验证。若仍无法辨识，回到源图重新设计强化刀盘外齿，而不是调战斗数值。

用户随后以截图绿框澄清，认可的是当前**强化齿刃状态的银灰色高级刀盘**，不是 `weaponSkin=bluegloss` 的基础蓝漆源图。此前“以蓝漆盘为高级标尺、重新设计基础态”的结论撤销。旧灰钢强化盘保持默认；六辐蓝色候选级差 FAIL 仍有效。下一项不再改已认可的齿刃盘，优先处理独立的“联动刀盘强化与已有两件设备难以区分”问题。

### 2026-10-06 联动表现修正

仅改 `saw-mount.mjs`：当同一车厢已有两件切割轮且获得联动强化时，前后轮中心间距由画面 44 增至 60，并在两侧增加连接前后刀盘的灰钢传动梁和端部轴承。这样仍是四个真实刀盘、两个装备占位，无额外数量角标；保留银灰色强化齿刃盘以及既有旋转色带。仅表现坐标改变，规则接触长度仍由原有 `sawLinked` 的 30→50 决定，伤害/间隔/碰撞不变。

`verify-saw-family` 两宽各九状态及新增 44/60 间距断言 PASS；`verify-saw-slots`、两宽三段远征胜负重开 PASS。标准网页客户端正常启动，截图/状态已看；起手尚无联动强化，升级态以真实战斗快照的表现对照截图 `output/saw-family-reach-base-390.png`、`output/saw-family-linked-base-390.png` 和 `output/saw-family-combined-legacy-320.png` 检查。静态看前后拉伸与传动梁可辨，暂记**候选通过静帧检查**；真实选卡后的动态体感、用户审美和微信真机未验证，不标为最终美术验收。
