# 站内构筑模块契约

## M2.1实施契约（2026-09-23，覆盖下方旧获取限制）

M2.2验证补充（2026-09-24）：商店可直接拖入周转；原载体move幂等，不重复计算自身体积。车厢详情模态阻断拖拽。下方旧“商店不能拖到周转”“容量不足不扣款”已失效，只有余额不足或非法商品拒绝获取；安装容量仍必须校验。verify-disposal.cjs、verify-drag.cjs及turnover系列覆盖新行为。Station本身无新异步资源，后台／真机生命周期总体验收留M5。

目标：满容量购买进入装备周转，满编购车进入reserveCars；车厢支持编入、移出、同级跨位置合成和主动处置。同种装备按配置sellValue出售，不按paid来源差异定价。非目标：真实广告、存档、战斗数值与新起手经济。

Train继续唯一拥有carriers、reserveCars、equipment；snapshot复制三个集合，战斗仅使用carriers及已装设备。新增attachCart/detachCart/removeCart，返回失败时不修改状态；merge保持已编组车厢位置，否则保留周转结果。Station协调同步扣款，commandId去重范围为本实例；出站检查两类周转。公共命令新增attachCart、detachCart、sellCart、discardCart；确认由既有展示流程完成。无新事件、线程、计时器或平台依赖，dispose语义不变。

本轮有限90废料夹具限制可购入规模，出售小于买价且合成不增值；不设容量拒购门槛。未来奖励入口加入前须核查完整收入上限；M3复查该边界。持久化、真机性能及完整生命周期未验证，TEST_STANDARD尚缺按入口规范验收。验证：verify-turnover.mjs及verify-turnover-ui.cjs；旧容量拒购断言需迁移，不能再作为新需求判据。

占位修订：每件已装装备一个连续跨格块，图标居中、格数角标；单行容量轨道避免形状装箱约束。拖影尺寸从目标轨道与data-size计算，跨车切换后重算；纯表现，不改变容量/费用。此规则覆盖旧首格图标+圆点展示。

## 拖动装配试作
BrowserAdapter下drag.mjs拥有Pointer监听、单次拖动状态及浮动图标，移动8px开始拖动，松手一次性发命令；Bootstrap协调既有buyModule/move，Game验证容量/余额并原子扣费。悬停列车立即切换目标。商店不能直接拖到周转，无效落点只提示，不修改资源。pointercancel/blur/后台取消，stop注销全部新增监听和清理浮层。未添加独立循环/计时器。绿框仅代表可投放区域，容量/余额最终由Game校验；未实现占用格预览或任意格位保存，仍为容量自动排列。真机触控与Pointer取消事件尚未实机验证。

最新展示修订：容量逐格显示，装备首格SVG图标，附属格圆点并共用装备ID；自动按顺序表达占用，禁止额外几何放置限制。Bootstrap拥有inspected展示ID，点击后弹出详情及处置命令，装卸后关闭。商店图标直接购买，周转图标点选后装入。验证入口verify-grid.cjs；价格/体积/归属仍由Game控制。

## 最新固定分区修订
已装装备在上、列车居中、商店与周转在下，底部买车/合成/出站。普通整备无滚动；已装与周转分别每页1件并显示总数，避免小屏处置按钮被遮挡。页码仅Bootstrap展示状态，切车清零，列表缩短时显示页码自动夹紧；无经济副作用。4件商品同屏。Adapter兼容无滚动容器。旧滚动布局描述由本段覆盖。验证入口verify-fixed.cjs；旧verify.cjs与verify-station-layout.cjs依赖完整列表/滚动容器，尚待迁移，不能宣称本次全量回归完成。

## 整备站竖屏布局增量
用户修订：移除整备站怪群，战斗围堵保持不变。已装装备列表置于滚动区首位；切换所选载体后Adapter回到列表顶部，同载体普通操作保留滚动位置。通过展示属性data-equipment-owner识别内容变化，不读取Game内部状态。
目标：与战斗共用桌面9:16/手机真实视口规格。上部补给、周转、选中车厢装备内部滚动；下部固定列车（车头朝右）、买车、合成、出站。现有命令与费用不变。BrowserAdapter保留站内内容滚动位置，切场景重置；CSS布局无新循环。确认框限制在设备外框且可内部滚动。验收：320×568及桌面外框比例、5车厢可见、内部滚动不移动底部、既有构筑/战斗回归。正式横向进站动画不在本轮；真机舒适性待用户体验。

版本0.1；执行角色：本轮开发者；状态：实现中。公共入口 station-prototype/src/game/station.mjs。

负责买车、装备安装/卸下、同阶车厢合成、周转、出售/丢弃、出站检查；不负责战斗、模块升星、广告和正式存档。

Train拥有载体与模块归属，Economy拥有钱包；Construction协调同步事务与运行状态。配置由bootstrap注入。Presentation仅生成HTML与绘制描述，BrowserAdapter操作DOM/Canvas，Bootstrap装配；无新增事件总线和调度器。

API：snapshot返回深拷贝；dispatch接收递增整数commandId、命令及目标ID，返回ok/message，拒绝重复/过期序号。费用单位废料，体积单位容量。同阶合成仅支持非车头且小于三级；两车装备全部进入周转区，由玩家重新分配，其他载体不变。购买模块需明确选中有容量的载体，容量不足不扣款。

合成和丢弃使用界面预览确认；纯规则接口是确认后的提交入口。UI确认期间锁定背景输入。出站要求周转为空，成功后只显示本轮完成页，不伪装战斗已实现。

生命周期：创建即初始化；无后台任务、无tick、无异步结果；dispose后拒绝命令，重复dispose安全。Adapter start只注册一次、stop注销事件。重开新实例与序号，旧实例释放。

容量上限44，模块最小体积1；测试配置固定。不增加无限仓库；卸下仅站内允许，所有周转装备必须处理完才能离站。站内页面刷新会重置夹具，界面明确提示，正式站内中断存档待接入。

性能：事件驱动，无循环和后台计时；目标机预算待PERFORMANCE规范制定，性能未验证。测试检查钱包不为负、逐载体容量、装备守恒、同阶约束、出站限制和释放。文档TEST_STANDARD、CONCURRENCY、PERFORMANCE尚不存在，执行入口规范与本契约。
