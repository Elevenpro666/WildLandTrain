# 出站护栏演出

目标：打开战斗页的第一帧就是300米/秒冲刺；屏幕下方的两段护栏标识整备站边界，中央留出轨道通道；护栏外前方有六只怪堵路。镜头先固定在站口，列车从屏幕下方高速越过护栏和怪群，约0.8秒冲至屏幕顶部；随后镜头追随，冲刺结束再追上减速列车，使其回到中部。非目标：改变冲刺距离、怪群碰撞或资源结算。局内手动冲刺也使用同一300米/秒速度，避免同一能力有两套规则。

验收：320/390宽首帧护栏在屏幕下方、怪群在护栏外的前方、车头刚从下方冲入；战斗时钟和无敌冲刺从出站同帧开始，没有独立准备阶段或起步加速。首段场景速度第一帧即960单位/秒，镜头静守站口，约0.8秒车头到顶部；护栏附近无停顿或二次启动。镜头接上后，冲刺结束时追赶列车回到中部。高阶蝎初次攀附先蓄势，不再同帧造成无提示伤害。

职责：`battle.step(dt)`从首帧正常推进。`departure.mjs`只读战斗主时间和既有场景路程，计算镜头相对列车的偏移；地表与所有实体共享该偏移，保证相对移动不失配。两段护栏是只在出站开头可见的表现层。高阶蝎首次攀附由战斗规则设置一次0.55秒蓄力，后续仍沿用原攻击间隔；表现层读取原`attackTimer`制作张钳后撤、短暂停顿、前扑与回收。

依赖与生命周期：无新循环、无独立演出计时或新可变服务；暂停/选卡由既有战斗逻辑管理。护栏和动作不加载新位图，旧素材保留。镜头方案仅在`art=approved`入口启用，其他入口沿旧逻辑。

验证：`verify-station-exit.cjs`检查两宽首帧护栏/怪群、战斗立即推进、0.25秒过栏、0.8秒冲顶和减速回中；`verify-no-recoil.mjs`检查首0.6秒保持全速、镜头不倒退及后续冲刺；`verify-speed-continuity.mjs`检查即时全速和冲刺末平滑回巡航；`verify-scene-distance.mjs`检查业务300米/秒与场景960单位/秒映射；`verify-full-expedition.cjs`和`verify-contact-loop.mjs`检查战斗回归。视觉确认仍需用户在实战动态画面中判断，微信真机性能与提速后的平衡调优未验。
