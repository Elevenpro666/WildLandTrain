# 荒野列车架构规范

版本：1.0。状态：目标架构，新增与迁移代码遵循；不代表现有原型已通过检查。依据 AGENTS.md 和用户提供的工程规范附件。本轮只建立规范，不迁移代码、不更换引擎。

## 1. 分层与依赖

以下是源码直接引用的允许范围，未列出的跨层依赖禁止。接口和数据契约跟随定义层归属，不能以“只是接口”为由反向引用。

| 层 | 职责 | 允许引用 |
|---|---|---|
| Core | 时钟接口、随机数接口、状态机、事件与池等通用机制 | Core 内公开接口，标准语言库 |
| Framework | 通用生命周期、调度、资源与存储端口 | Core、Framework 内公开接口 |
| Services | 输入、资源、音频、存档等项目级能力 | Core、Framework、Services 的显式公共接口 |
| Game | 行程、列车、战斗、敌人、经济和构筑规则 | Core、Framework、Services 公共接口、声明过的 Game 模块接口 |
| Presentation | HUD、镜头、特效和场景展示控制 | Game 只读契约与命令接口、Services、Framework、Core |
| Adapters | 浏览器或微信平台 API 的具体实现 | Core、Framework 的端口定义、对应平台 API |
| Bootstrap | 选择平台、构造对象、注入依赖、启动和关闭 | 各层公开入口 |

同层引用仍必须无环。Core 不出现列车、敌人、金币、武器等业务概念。Game 与 Presentation 均不直接调用 DOM、Canvas、wx、文件或网络 API。Presentation 生成绘制描述，Adapters 实际绘制；Adapters 不引用 Game 或 Presentation。

平台无关的 RenderPort、StoragePort、LifecyclePort 等接口定义在 Framework；实现由 Bootstrap 注入。禁止在业务中使用服务定位器或根据浏览器/微信分支动态寻找依赖。

## 2. 建议目录

```text
src/
  core/
  framework/ports/
  services/
  game/{journey,train,combat,enemies,economy,construction}/
  presentation/{battle,station,hud}/
  adapters/{browser,wechat}/
  bootstrap/
configs/
assets/
tests/{unit,contract,integration,e2e,performance}/
Docs/{modules,adr}/
```

目录按实际功能逐步建立，不为满足目录图创建空框架。模块通过 index 等明确公共入口导出，其他模块不得引用其 internal 实现。现有 H 盘原型保持原位，正式迁移需另开任务。

## 3. 模块职责与资源所有权

| 唯一 Owner | 拥有和可修改的数据 | 不允许承担 |
|---|---|---|
| RuntimeLoop | 唯一帧调度、阶段执行、启动停止 | 伤害和经济规则 |
| TimeService | 模拟时间、暂停原因集合、时间基准 | 私自推进业务状态 |
| InputService | 输入订阅、坐标归一、命令队列 | 扣费和伤害计算 |
| Journey | 行程状态、速度阶段、段数、切换代次 | 直接旋转场景或修改生命 |
| Train | 车厢身份、顺序、槽位、生命、配置变更 | 生成敌人和绘图 |
| Enemies | 敌人实体、生命、位置与行为状态 | 修改 Train 内部集合 |
| Combat | 攻击计时、命中与伤害计算、战斗结算事件 | 直接修改 UI、钱包或其他模块内部状态 |
| Economy | 钱包、报价快照、购买事务记录 | 渲染商店与调用广告 SDK |
| Construction | 构筑命令验证与操作编排 | 重复持有权威车厢或钱包副本 |
| CameraPresenter | 当前镜头、过渡进度、只读世界到屏幕映射 | 改变战斗规则和世界坐标 |
| ResourceService | 加载去重、缓存、引用与释放 | 模块私自持有失管资源 |
| SaveService | 存档队列、版本、存储端口 | 绕过公共恢复接口修改业务状态 |
| AudioService | 声音句柄、并发限制与生命周期 | 业务模块直接创建音频对象 |

Combat 通过 Train、Enemies 公共命令提交伤害；实体 Owner 返回应用结果。击杀事实只由对应 Owner 发布一次。Economy 根据唯一奖励 ID 去重发奖。模块可以持有只读快照，不能把快照作为另一份权威状态。

## 4. 状态与镜头

主流程：Boot → Menu → Journey → StationEntering → Station → Journey；失败进入 Result，重开创建新的运行上下文。

Journey 内部阶段：高速出站 → 中速 → 低速 → 临停 → 高速突围。阶段是否启用、时长和退出条件由行程配置定义；当前原型的固定时长不是正式产品常量。

- Journey 统一决定速度、可受伤规则、允许的敌人类型和状态退出条件，Combat 与 Enemies 读取其只读策略。
- 高速阶段伤害被规则拒绝；普通地面怪不能只靠屏幕位移追上高速列车。低速允许贴车攻击，临停按遭遇规则处理路障和精英。
- 战斗坐标采用屏幕左上原点、x 向右、y 向下的展示约定；车头在列车上端，背景向下滚动。业务距离、速度需标明单位，不能直接混用像素和世界距离。
- StationEntering 时停止战斗生成与伤害处理，CameraPresenter 将列车绘制为车头朝右、从左向右进入。禁止通过旋转权威实体位置实现镜头切换。
- 镜头完成事件携带运行 ID 与切换代次；Journey 只接受当前代次，随后开放 Station 输入。过期回调、重复回调不得二次发奖励或开放错误界面。
- 暂停是独立原因集合，如用户暂停、切后台、升级选择；移除一个原因不能解除其他暂停。后台恢复重置帧时间，不追算离线战斗。

## 5. 数据流与一致性

输入 → 有类型的 Command → Owner 验证并更新状态 → 已完成事实 Event → HUD、特效、音频等订阅者。

命令带必要的 commandId、runId 和目标 ID；拒绝时返回稳定原因，如余额不足、车位已满、阶段不允许。事件不承担隐式请求/响应，不允许监听器在事件派发中重入购买或伤害结算；新命令进入下一逻辑阶段。

购买是原子操作：Economy 校验当前报价、余额和命令去重；Construction/Train 提供容量验证与提交接口。同一主线程事务内完成扣款和构筑提交；失败不扣款或完整回滚，不能跨 await 保留半完成交易。提交完成后才广播购买事件。

价格、伤害、敌人曲线等从配置读取，加载时校验类型、范围和引用 ID。存档只保存可序列化业务数据与版本，不保存平台句柄、监听器、计时器或画面对象。

## 6. 生命周期与统一调度

Bootstrap 构造依赖后执行 initialize → start；退出按反向依赖顺序 stop → dispose。initialize/start/stop/dispose 的重复调用必须可安全拒绝或幂等处理，并在模块契约中写明。

每帧统一阶段：输入收集 → 固定步长逻辑 → 命令与事件结算 → 展示更新 → 绘制 → 清理。碰撞在逻辑阶段执行，不再建立第二套循环。固定步长、单帧最大补步数及过载策略由后续性能规范配置；超载必须有计数，不可无限补帧。

模块定时工作注册到统一调度器并持有取消句柄；停止时注销任务与事件。适配器回调只转成输入或生命周期消息，不直接改变战斗状态。随机数与时钟可注入以支持复现。

## 7. 架构门禁与迁移

后续自动化检查至少覆盖：禁止的依赖边、循环引用、绕过公共入口、Game/Core 平台 API 泄漏、重复帧循环、未声明模块依赖。静态工具无法证明的所有权、事务、生命周期和晚到回调，由契约评审及测试补充。

当前尚未安装架构检查器或 CI。本规范通过不等于实现通过。每次检查记录 PASS、FAIL、未验证或不适用及依据。

遗留原型逐模块迁移，建议顺序为配置与可控时钟 → 平台适配与统一循环 → 行程和镜头 → 战斗实体 → 经济构筑。每步保留可运行入口和回归证据；迁移前后的规则差异单独记录，禁止借重构暗改数值。

新增依赖边、改变 Owner、引入引擎/Worker 或更换运行模型须先记录 ADR；是否需要用户确认按 AGENTS.md 的授权范围规则处理。
