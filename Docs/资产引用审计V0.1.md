# 美术资产盘点与引用防错 V0.1

日期：2026-10-15。状态：分批治理中；本版覆盖原型武器清单，以及车头、车厢、助推器、电弧本体和电弧升级件的语义引用与内容修订校验。

## 本轮目标与边界

目标是建立可执行的资产引用检查，阻止运行代码指向缺失或未登记的武器图。非目标：本轮不迁移渲染架构、不批量删除候选图、不声称完成全项目资产清理，也不启用CI。

责任边界：`station-prototype/assets/weapons/weapon-assets-manifest.json`是武器资源清单；`verify-weapon-asset-references.mjs`负责扫描静态引用并补入注册表中的武器资源路径；`src/presentation/art-asset-registry.mjs`是列车、助推器、电弧本体和升级件的语义ID注册表；`verify-art-asset-registry.mjs`校验资源路径、SHA-256内容修订、运行ID及功能绑定和模块导入修订；`verify-branches.mjs`是检查接入的主回归入口。

验收条件：生产代码中静态可见的`assets/weapons/*`路径均在清单且文件存在；清单无重复ID或路径；每条清单路径有运行引用；已拒绝/取代资源不混入活动清单；已清理的旧候选不能被代码或清单重新引用。

## 当前盘点与处置

- 运行中武器图：27项，全部写入清单并通过双向校验。`candidate`仍表示玩家视觉验收状态，不因“代码正在调用”自动转成已批准。
- 安全删除3个已确认淘汰且无运行/测试引用的文件：`arc-count-branch-overlay-v2.svg`、`arc-count-fork-jaw-v1.svg`、`arc-count-induction-rings-v1.svg`。删除前逐项检查绝对路径在`station-prototype/assets/weapons/`内。本目录无Git仓库，本地无法通过版本控制恢复；不保留这些图像的备用副本。
- 仍在运行的兼容资源暂不视为垃圾：`boost-module-v1-candidate.png`还由旧挂载分支引用，必须先迁移或退役该分支再评估删除。
- 其它无字面引用的图暂不自动删除：其中可能是动态选择、源稿、候选或评审素材。静态无字面引用不足以证明淘汰。

## 防错规则

新增或替换武器图片/SVG时，必须登记唯一ID和相对项目路径；执行`node station-prototype/verify-weapon-asset-references.mjs`。此检查双向比对清单和`src/`、`configs/`运行代码，核对文件存在、引用唯一性和淘汰状态。日常回归`node station-prototype/verify-branches.mjs`已导入此检查。当前没有CI，所以尚非自动提交阻断。

第1轮仅治理武器静态路径，因此当时尚不能防止把一张仍登记的有效图分配给错误功能；第2轮已对列车与助推器关键图建立语义ID和内容修订门禁。后续仍需按类别扩展敌人、地貌、HUD和整备站资源。用途和来源未确认前不批量清理剩余文件。

## 第2轮：列车与助推器关键图

登记11个稳定ID：车头/车厢当前图、四格平台候选、兼容图；助推器尾排基础、强化涡轮、强化火箭、侧裙短舱和兼容图。运行时用ID选择文件，图片URL追加SHA-256前16位`rev`参数；车体/武器渲染模块之间的关键ES-module导入地址也用目标模块SHA-256前16位修订，防止浏览器继续命中旧模块。文件内容变化但资源或模块修订未同步时，校验失败。`candidate`与`compatibility`状态不等同于玩家批准；资源接入运行不改变美术审批状态。

当前治理仅覆盖`train-body.mjs`与`weapon-feedback.mjs`中的上述资源；其余武器、无人机、敌人、地貌、整备站和HUD资源仍待分批迁移。授权/来源证明未在本轮补录；无静态引用不等于废弃，来源和用途确认前不批量删除。

## 第3轮：电弧本体与升级件

再新增12个ID，注册表累计23项。包括3种当前实际用于基础或叉口电弧本体的M18候选图，以及高压/脉冲电容、射程传导器、三级感应环、单/双高压候选、射程天线。电弧的渲染映射改用稳定语义ID；`approvedSprite`用`@ID`解析注册表资源，升级SVG和本体PNG的URL均追加内容哈希修订参数。修订后的ES模块导入链由校验器检查，避免热更时旧模块引用留存。weapon-assets清单校验读取注册表中的`assets/weapons/`路径，因此迁移为动态URL后仍保持27项双向核验。电弧本体与各升级部件仍为候选/旧源状态，不等于玩家验收通过；没有删除资源。
