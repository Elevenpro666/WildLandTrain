# 武器升级部件与逻辑规则 V0.1

日期：2026-10-08。状态：升级生产基准；横向往复刀盘已按用户确认进入浏览器原型，助推等级仍为待确认提案。先忽略此前的生图提示词，只依据功能、装配包络和实际运行规则设计部件。

> **边界更新（2026-10-15）**：第3节助推器升级提案已撤销，不再用于武器系列、装备购买或冲刺距离。助推器退出装备系统；冲刺只受车头品质及“整备站出站/路途中”两档规则控制。其余三类现役武器升级映射继续有效。详见[武器系列化与车头冲刺能力边界 V0.1](./武器系列化与车头冲刺能力边界V0.1.md)。

## 1. 统一语法

1. **装配数量 ≠ 升级等级**：每购买一件装备，就占一处合法实体装配位，场上必须逐件可数。现有强化卡按武器**类型**对本列车同类设备共同生效，并非挑一件升级；不得画出额外安装件来解释强化。
2. 每类装备固定底座、车体接口、最大静态/动态占位；升级只更换明确的功能子部件及其工作反馈。不得用整体放大、换色、加螺丝或增加无功能结构代替能力变化。正俯视、小屏可读、承力路径和与邻件净空是前置条件。
3. 两条强化路线可以兼修，分别修改自己的部件；不能以“基础／中级／高级”一张整机图覆盖所有卡片组合。可用基础本体＋路线部件层＋工作特效组合，避免指数级生图。
4. 升级外观与升级后攻击表现是同一升级语义的两个层次，但生产有先后：**先落地武器本体可见的结构变化，再制作攻击／命中特效**。结构变化必须对应实际存在且承担该能力的部件，玩家在390×844游戏尺度能看见、认出；特效不得代替本体升级表达，也不得把本体结构的数量误读成攻击目标数。
5. 禁止仅由数值推导出虚构硬件。例如目标上限从3增至5，不代表武器要增加五个实体输出口；若没有已定义、真实承担功能且适合装载的部件，不得先造一个“分配器”来解释数值。应先核对现有武器外观和真实升级机制，定义本体如何变化，再制作工作特效；特效与权威战斗数据同步。
6. 不改变头厢宽74 B、车距85 B、四格T及尾排P的已定安装框架。具体尺寸、运动净空以现有装配包络文档和实测为准；没有通过净空的升级不得转默认。

## 2. 已实装攻击武器：部件与规则一一对应

下表数值抄自 `station-prototype/src/game/upgrades.mjs`，为当前运行值，不是建议值；每张卡仍按现有前置关系生效。

| 家族／路线 | 卡片与前置 | 唯一承担升级的部件 | 当前效果及玩家可见证据 |
|---|---|---|---|
| 切割轮·覆盖 | `sawReach` | 侧向承力支架与刀盘工作位 | 横向覆盖55→70；支架伸出且刀盘真实触及更外侧敌人，不增加刀盘数。 |
| 切割轮·覆盖 | `sawLinked`，需`sawReach` | 车侧短横向伸缩臂 | 前后半长保持30，刀盘最远横向覆盖70→90；不增盘、不改每次伤害或间隔。刀盘与命中窗口按同一模拟时间横向运动；见第4节的净空边界。 |
| 切割轮·切削 | `sawDamage` | 刃缘／齿形与切削材质 | 每轮8→12；工作刃更有力，银灰高级刀盘作为既有视觉基准，不增加盘数。 |
| 切割轮·切削 | `sawRate`，需`sawDamage` | 主轴、电机与传动轮 | 间隔0.5→0.35秒；旋转色带和接敌节奏加快，不靠静态锈迹或多盘表达。 |
| 电弧·传导 | `arcReach` | 输出叉口及绝缘导向端 | 跳跃距离60→90；实际电弧路径更远，炮口数不变。 |
| 电弧·传导 | `arcCount`，需`arcReach` | 沿用基础壳体、能量核心与两个原攻击端；本体内部增加并联铜质导能通道（可操作对照候选，待玩家目测），不增发射端。多级导体必须完整收在单个T位包络内。 | 不同目标上限3→5；同一攻击端沿链传导至更多目标。车体上以“单通道→双通道”表达武器承载／传导能力，不把通道数等同目标数；攻击特效后续再增强。 |

### `arcCount` 单个T位尺寸约束（2026-10-08）

- 车厢单格T位是18×20 B的静态实体上限，四格中心纵向间距23 B；升级态也不能跨格、覆盖邻格或挤占其他武器的工作空间。
- 当前M18 V5横向长图不适合作为单T武器本体；代码试演分支仍有26 B宽绘制，普通挂载多件布局会绘至54～68 B。该候选因此不符合T位尺寸约束，不能视为已定稿或直接作为单格装载美术。
- 下一候选改为纵向紧凑构图：同一个壳体内沿车体纵轴分层表现两道直线传导通道，中央单一能量核、首尾各一个原攻击端；最终源图有效内容须按18×20 B比例适配并留透明安全边。若识别性无法在此包络内成立，应重设计结构，不通过缩小到不可读或跨占多个T格补救。
| 电弧·放电 | `arcDamage` | 铜绕组、储能芯与主输出端 | 首目标12→18；同一攻击端的蓄能与命中更强，不能只增加线圈匝数／装饰线。 |
| 电弧·放电 | `arcPulse`，需`arcDamage` | 储能开关／并联放电通道 | 0.15秒后再击首目标一次、不再次连锁；可用同一核心向同一炮口两次蓄放电，不能读成第二台装备。此前并联通道大图**尚未**锁定为此卡的生产资产。 |
| 无人机·巡防 | `droneCount` | 机舱发射口与实际无人机 | 每舱1→2架，不占额外列车容量；两架机体和两个出舱动作都要可见，不用数字代替。 |
| 无人机·巡防 | `dronePatrol`，需`droneCount` | 感知／通信组件 | 巡航范围180→240，并优先分散目标；雷达覆盖及飞行分配可见，不再增加舱数。 |
| 无人机·处理 | `droneDamage` | 机载电极 | 接敌伤害14→20；电极工作端和命中强度改变，不增机体数。 |
| 无人机·处理 | `droneFocus`，需`droneDamage` | 锁定传感器／目标处理器 | 同舱优先集中攻击最大耐久目标；共同锁定线、转向和攻击目标一致，优先于分散策略。 |

`supply` 是可重复的全局攻击供能卡，每层伤害+10%，不影响冲刺；它不是某件武器的实体等级，也不生成第四类“高级外壳”。现有卡每张只取一次，前置卡顺序保持不变。

## 3. 助推器：先定能力轴，再生产升级图

当前运行规则只有**每装一件助推器增加120玩法米初始冲刺距离**；冲刺速度默认500场景单位／秒，常速120场景单位／秒，1玩法米=3.2场景单位。距离由车头品质基础值加各件助推器距离决定；助推器没有现行升级卡或单件等级。旧《短助推器基础与强化视觉方向V0.1》把120误写为“场景单位”，以运行配置的“玩法米”为准。

建议的升级轴只改变**冲刺距离**，不混入速度、伤害、第二冷却或额外无敌规则；同一类助推器的升级仍作用于已装各件，不创造额外实体。提案为：基础短机组每件+120玩法米；一级强化**涡轮转子／进气环**，每件+150玩法米；二级强化**短火箭钟形喷口／导流喉部**，每件+180玩法米。一级必须先于二级，升级数值是待确认建议，**不得直接写入游戏**。四件装配始终是四件，喷流一件一股；二级喷口仍须压在15×12 B单孔及既定后车净空内。升级不会改变500场景单位／秒的冲刺速度，时长因距离增加而自然延长；减速与常速解除无敌的既定规则不变。

## 4. 明确冲突与冻结项

- `sawLinked` 原纵向往复会侵入后P位。用户确认后，浏览器原型已改为**横向往复**：侧梁短伸缩臂带动左右现有刀盘，中心纵坐标不变；卡片与攻击判定由前后30→50改为前后30不变、最远横向70→90，伤害／间隔／盘数不变。表现与命中共用模拟时间及位移公式，不会只在图上移动。390×844合法“1切割轮＋2尾排助推器”试演的12个时点中，盘到P本体理论净空为2 B、无几何穿插；但这是**零额外容差的边界值**，喷流、高级厢多刀盘和微信真机仍未验证。横向伸缩臂只是可运行原型，不等于正式美术定稿。
- 助推器两级及120→150→180玩法米是新提案，与当前“无强化等级”的规则不同。用户确认前只作为设计映射和资产规划，不进入正式游戏；已有强化图只是视觉候选，不反推数值或等级。
- 电弧多级传导的本体升级表现候选：基础态与升级态沿用相同外壳、青色核心和原有两个叉口；升级只在本体内部增加一条并联铜质传导路径，并回接到原有两个攻击端，不新增发射端、不改变攻击分叉形态。候选沿用基础图比例，统一18 B宽，约12.63 B高，限制在18×20 B单T包络内。实现为游戏直接加载原基础PNG，再叠加透明矢量通道，避免外部PNG嵌入SVG时被浏览器屏蔽。此表现仅对应既有`arcCount`连锁目标数强化，攻击规则和数据不改；仍待玩家目测连续性与小屏辨识度确认。
- 其他电弧并联通道、现有高阶舱体等大图只作为形态候选；没有通过真实T/P尺寸和实际攻击反馈验证前，不自动等同任何强化卡。

## 5. 资产制作与验收顺序

先做每类装备的一件基础本体和一张标注功能部件的正俯视结构图；然后按单卡做**一个部件变化＋对应动作**，最后验证双路线叠加。同一轮只验一张卡的能力表达。390×844为日常唯一基准视口；须在真实游戏中同时检验空载、单件、合法满载、攻击／冲刺工作态及相邻设备净空。通过标准为：遮住卡名仍能分辨“多一件”还是“原件变强”，且玩家看见的作用范围／节奏与运行数值一致。大图好看、图片可加载或静态截图可数均不足以通过。

本文件确定部件职责和运行／待确认规则；横向刀盘已在浏览器原型运行，但不代表所有高密度混装已通过或新增助推等级已上线。
