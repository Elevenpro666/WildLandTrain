# 荒野列车产品信息层级规范 V1

日期：2026-10-05。状态：初始设计基线，待实际界面验证。适用：竖屏战斗、站点构筑、升级选卡、结算与局外成长。本文规定信息如何组织，不新增玩法、货币或成长门槛，不代表界面已经全部实现。

核心原则：战斗先看清威胁与行动，站点先看清收益与代价，成长先看清哪里变强。重要信息有稳定位置，但不必持续闪动或铺满屏幕。

## 1 信息优先级与展示方式

优先级、是否常驻、绘制层是三件不同的事。资源重要所以常驻，遇到攻击预警时却不应抢过危险；选卡覆盖战斗，是因为进入决策状态，不代表选卡始终优先于生存。

| 优先级 | 玩家要知道什么 | 典型内容 | 展示原则 |
|---|---|---|---|
| 一级 即时生存与行动 | 现在有什么危险，我能做什么 | 敌人攻击前摇、列车受击和低耐久、冲刺是否可用 | 以战场动作和稳定控件表达；危险发生时可短时增强，不用常驻解释句 |
| 二级 核心进度与资源 | 我成长到哪里，还能花多少 | 经验进度、废料余额、当前装备效果 | 固定位置清晰可查；变化时局部反馈，平时保持安静 |
| 三级 战术预期 | 哪里有怪，下一轮是什么 | 小地图、怪物出现进度、精英与 Boss 预告 | 常驻但紧凑；关键遭遇开始时短暂提高关注度 |
| 四级 选择依据 | 选择后具体改变什么 | 商品成本与容量、技能卡收益、升级前后对比 | 在相应选择界面完整展示，不长期塞进战斗 HUD |
| 五级 解释与历史 | 为什么、详细规则是什么 | 教学、完整属性、图鉴、战斗统计 | 首次需要时或主动查看时展示；没有入口的内容标记待设计，不擅自增加按钮 |

## 2 战斗画面布局

沿用已确认决定：全屏为战斗区域，HUD 是局部覆盖，不恢复上下大面板。以下是信息位置示意，不是最终美术稿。

```text
┌──────────────────────────┐
│ 小地图              经验图标＋进度 │
│ 出怪进度            废料图标＋余额 │
│                          │
│       ▏车头与交战区       Build区 │
│       ▏车厢与铁轨                 │
│                          │
│                    无敌冲刺按钮 │
└──────────────────────────┘
```

| 组件 | 常态与位置 | 按需增强及退出 |
|---|---|---|
| 小地图 | 左上独立展示层；表现实际可感知敌人的位置与数量 | 普通、精英、Boss 用点形与尺寸区分，颜色辅助；不能凭空显示未生成敌人。密集时可聚合计数，不用一个点假装一只 |
| 出怪进度 | 小地图正下方；普通、普通、精英、普通、Boss 等节点取自当前关卡配置 | 当前节点突出，已完成和未出现区分；不重复添加到站距离。出生动画进度不能冒充整关波次 |
| 经验与废料 | 右上独立资源组；经验在上、废料在下。图标＋必要进度或数值，不加重复名称 | 掉落飞入对应图标，短脉冲确认；连收合并表现，不遮住数值、不改变结算 |
| 列车耐久 | 车头左侧窄竖条，表达整列共用血量，不区分车厢；不放在车头上方或屏幕左侧中部 | 自下向上填充，损失时从顶部下降；受击短暂提亮，低耐久增加警示图形，不只靠颜色。平时不显示耐久文字或精确数字，具体尺寸与遮挡仍需动态验证 |
| 无敌冲刺 | 右下，避开铁轨；充能只在按钮内部表达 | 充满、释放中、Boss 封锁有不同图形状态；只保留一套恢复进度，不加独立冷却行 |
| 肉鸽 Build 展示区 | 右侧资源栏下方展示已获得技能图标；替代原第5项加速预留，不是技能释放区 | 按关联武器归组，同类叠加显示层数而非重复图标；获得或强化时短暂提亮。点击查看技能名称、关联装备和实际效果；过多时折叠展开，不无限向下堆。此为交互初案，尚未接入 |
| Boss 耐久 | Boss 战按需出现；建议上方中间紧凑区，不与两侧 HUD 重叠 | 死亡或离场后撤下；Boss 预警主要落在战场与进度节点，避免长横幅持续遮挡 |
| 武器强化 | 对应装备图标短反馈＋武器外观、攻击效果的持续变化 | 不使用“某某已强化”常驻文字；缺少资源先补清单，不能用说明文字代替资产 |

禁止回流：左上“高速无敌”解释行、冲刺范围大框、关卡内冲刺米数、距下站距离、无实际作用的按钮、战斗常驻文字强化清单。允许紧凑的 Build 图标区，详细说明按需展开。仅出站冲刺可短暂显示本次距离。

## 3 站点与选卡信息顺序

站点从“我有什么”转向“我能怎么变强”。第一视线是当前列车和装载状态，其次是可比较的候选，最后是出站操作；不把广告按钮做成唯一视觉中心。

候选统一按以下顺序组织：物品图标与名称 → 实际收益或作用 → 与当前装备的关联 → 容量与后续操作 → 获取成本。免费、废料购买、广告机会使用可比较的信息结构，不暗示只能三选一。

- 武器：展示等级或能力的真实变化，例如覆盖、频率、目标数；不只写“战力提升”。
- 车厢：明确单节容量、整列容量和编组位置的区别；不能把单节升级描述成整列必然扩容。
- 获取与装载分开：暂时装不下说明后续整理方式，不替玩家拒绝获取或播放广告。
- 未开放功能：显示真实章节或等级目标及解锁结果；没有配置时标记设计待定，不能捏造目标。
- 技能卡：展示关联装备图标＋名称、技能名、关键效果及真实前置条件；不加“基础装备”四字，不用装饰标签挤压收益信息。
- 合成：拖动预览展示合成结果及容量变化，完成后本体改变；不恢复冗余“选择合成”按钮。

教学只讲当前行动：先免费完成一次装载或升级，再让玩家看到攻击或空间的变化。首次说明可以有短文字，熟悉后不反复弹出；教学不强迫选择广告。

## 4 结算与局外成长

结算首层展示胜负或抵达结果、实际获得资源、继续路径；统计与完整构筑放次层。战败复活若已开放，应明确保留什么、恢复什么及成本，与结束本局同时可选，不用含糊文案隐藏损失。

局外成长首层为当前可实现的升级目标、实际收益、所需资源；下一章节或开放条件次之，完整属性按需展开。不新增综合战力分数替代具体成长说明。

国内 IAA 与海外混合变现保持同一收益说明结构。只有确实可用的获取方式才出现；免费路径不得被折叠藏起。广告说明增强哪一种体验或减少哪一种损失，付费与广告成本不可混写。

## 5 同时发生时的处理

- 危险前摇和列车生存反馈优先于收获脉冲；大量掉落合并飞行动画，资源真实数量不能丢失。
- 一次只展示一个阻塞决策界面。失败、选卡、进站等冲突由游戏状态决定，UI 不自判胜负；待处理奖励和选择保留，不能被覆盖消失。
- 选卡期间暂停战斗的既有规则保持；教程不遮挡需要识别的对象，不在攻击进行时强行讲解。
- 普通受击不弹文字框；广告失败、购买失败等必须说明原因，并保留资源和可恢复操作。
- 稳态不持续闪烁。等级、危险、禁用不能只靠颜色，至少再有图形或状态差异。

## 6 展示层与适配初始约定

战场、世界内状态反馈、固定 HUD、临时收获反馈、阻塞选择界面分层管理。小地图独立于地面滚动；资源组独立于小地图布局。纯展示层不截获触摸，弹窗打开时只让顶层接收输入。

以 390 宽作为排版参考，不把坐标锁死：左组左锚定、右组右锚定、操作区避开中轴；安全区包含设备边缘和平台胶囊。短屏优先压缩装饰与间距，不把关键数字和点击区域缩到难以识别。

V1 建议值待实测：间距使用 4/8/12/16 逻辑像素；关键数字与正文不小于 14，标题 18–20；可操作热区至少 44×44。HUD 灰阶底与有限强调色沿用产品资产，不照搬通用网站视觉。经验/废料在地面、飞行、HUD 中保持相同识别特征。

正式接入时，HUD 接收只读状态和变更事件，布局只负责表现；图标收取目标共用锚点。动画完成不作为真实奖励结算的唯一条件，暂停、跳过或切后台不能丢奖励。浏览器键盘验证需有清晰焦点，手机触控为主要验收方式。

## 7 验收与当前缺口

每次改动需在 320×568、390×844 及带安全区的真机检查：常态、密集交战、低耐久、Boss、满充冲刺、连续收获、选卡、站内空间不足和结算。真实试玩检查能否快速找到耐久、冲刺、资源及下一波；截图不替代理解度测试。

当前 M16 是美术验证夹具：已有左上独立雷达、下方单批出土进度、右上资源与收取终点；不等于真实关卡 HUD 完成。仍缺配套经验/废料图标、真实多波进度、精英/Boss 标记、完整耐久与操作区同屏验证。资源仍在原 Canvas，不宣称全部 HUD 已独立分层。

本轮验证：文档与最新用户决定核对 PASS；新规范界面落地、短屏适配、微信真机及玩家理解度均未验证。本轮没有修改游戏画面。

下一轮先按此规范整理当前 HUD 的信息分区与缺口示意，再补经验/废料配套资产和真实状态接入；不因文档完成就批量新增入口。
