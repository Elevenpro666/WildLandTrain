# 五系武器实体与表现分层审查表 V0.1

日期：2026-10-22｜用途：把槽位规范和用户确认的俯视层级原则转成逐武器核对表。此表是审查登记，不代表运行版已经有3D高度/碰撞或分层渲染实现。

## 判定原则

- **投影相交**只触发可读性检查，不单独判实体冲突。
- **实体冲突**：静态或活动实体的三维占据体积相交时，才是碰撞问题。
- **遮挡冲突**：关键武器被另一实体完全且持续遮蔽时，才是必须处理的辨识问题；局部/短暂遮挡可接受。
- **特效冲突**：效果域交叠可以接受；渲染次序、亮度/不透明度或持续时间使邻近武器长期不可读时才需调整。
- 下列“建议绘制层”是待采用的表现设计，不代表已实现。物理高度和渲染顺序是两套独立数据，不能从SVG先后顺序反推真实高度。

## 现有2D原型绘制顺序取证（仅作现状，不作为目标层级）

检查范围：本工程的 `station-prototype/src/presentation/battle.mjs` 等旧验证原型。其SVG大致按DOM顺序绘制：场景/道路 → 列车运动效果与车体 → 武器本体 → 血条 → 敌人 → 无人机锁定线 → 无人机飞行器 → Boss/冲刺效果 → 通用命中特效/受击反馈/拾取物。SVG后绘制元素会覆盖先绘制元素。

这能解释当前原型里部分机件会被后画敌人/特效遮住；但该代码是二维层序，不提供3D高度证据，也没有覆盖新的拒止/地雷/穿透五系规范。本表不把旧原型的绘制顺序宣称为新设计已通过。

## 当前挂载空间校验器的能力边界

代码核对范围：`station-prototype/configs/mount-fit.mjs`、`mount-layout.mjs`、`station-prototype/src/presentation/train-body.mjs`。

- `checkWeaponMountFit`只在同一载体内检查切割轮与助推器。将切割滑轨/刀盘与助推器转成X/Y矩形，矩形相交即返回不通过；数据结构没有高度Z、遮挡持续时间或渲染层字段。它能发现这组二维投影相交，但不能判定两者是否真实碰撞，因此对可能分层的构型会产生过度拦截。
- 校验器目前不检查轮组、车体边梁、无人机、拒止器、地雷投射器、弹体/落点或邻槽武器；“未报告冲突”不能理解为这些组合已通过。
- 运行原型车宽配置为74 B；武器槽新设计基线为70 B。当前`trainBody`的approved车厢主体绘制高度也按70 B计算，但轮组主要是车体纹理/窄滚动线，并没有与切割件共用的体积边界。现有战斗画面是分层SVG/2D实体布置，不含可直接读取的物理Z数据。
- 所以当前结论应分为：静态槽位几何可按70 B设计基线核算；旧校验器的切割轮/助推器二维重叠结果只能标记“需要立体与可读性复核”；新车轮—切割轮实际碰撞、其余五系碰撞和渲染遮挡均为“未验证”。不得直接把旧校验器的FAIL当作物理冲突，也不得把未检查的组合标成PASS。

### 后续校验规范（尚未编码）

每个部件提供统一坐标系下的`x/y/z`实体包络；运动件提供覆盖完整动作周期的联合包络；碰撞判定只比较实体包络，投影相交则单列可读性检查。渲染层和特效时序单独登记，不用Z值代替绘制顺序。实施前必须先从载体/轮组/武器正式侧剖资料确定高度区间；未知区间保持“未定”，不可填猜测值。
