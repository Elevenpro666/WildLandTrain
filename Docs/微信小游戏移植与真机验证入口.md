# 微信小游戏移植与真机验证入口（首轮）

状态：2026-09-30 已建立独立小游戏 Canvas 可检查版；浏览器同画面完整流程通过，开发者工具已打开工程；**微信模拟器画面与手机真机仍未验收**。

## 现状与边界

- `station-prototype/src/game/` 与 `configs/` 为可脱离浏览器运行的规则层。`verify-platform-boundary.mjs` 检查平台引用，并在无 DOM 的 Node 环境推进出站冲刺、Boss 打断和冲刺禁用。它是移植前置门禁，不等于小游戏运行通过。
- `src/bootstrap/main.mjs` 与 `src/adapters/browser.mjs` 依赖 `window`、`document`、HTML 按钮和 `requestAnimationFrame`；`src/presentation/` 输出 DOM／SVG 字符串。这些界面不能直接当成小游戏 Canvas 页面使用。浏览器地址 `127.0.0.1:4186` 只是网页验证入口。
- 本机微信开发者工具已用 `open --project` 成功打开 `wechat-game`。工程包含 `game.js`／`game.json` 与测试 AppID；CLI 返回打开成功不代表模拟器编译或真机通过。

## 下一轮实施顺序

1. 已建立 `wechat-game`，保留网页原型；共享 Game 规则，Canvas 有唯一帧循环、触摸命中与后台暂停。
2. 已实现出站、三段自动战斗、三选一强化、手动冲刺、Boss 锁定、横向入站、站内购买／装载／周转／合成与结算重开。九张运行图由原透明素材压缩生成，约 102 KB；原图不动。
3. 下一项在微信开发者工具模拟器中验证实际编译、触控和错误日志；随后用实际手机检查视觉、操作和帧率。开发者工具与手机结果分别记录。
4. 真机性能测量前指定设备、运行时长与统计口径；Boss 主观美术和玩家是否看懂强化、掉落、冲刺另列真人验证，不用自动化测试代替。
