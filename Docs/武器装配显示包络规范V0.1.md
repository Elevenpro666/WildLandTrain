# 武器装配显示包络规范 V0.1

日期：2026-10-07。状态：**当前候选平台的执行规范，尚待玩家视觉确认**。适用 `platformArt=carV1` 的390×844战斗画面；B 是SVG绘制单位，不是行进距离单位、源PNG像素或装备容量。车头/车厢均宽74 B、车厢长约94 B且不随等级放大。旧《列车武器挂载分区与尺寸规划V0.1》第4节是尚未落地的初轮估计；同一候选平台以本文实测包络为准。

## 接口与尺寸

| 接口/装备 | 锚点与显示包络 | 净空和识别门槛 |
|---|---|---|
| 车厢T四格 | 格心横向间距20 B、纵向间距23 B | 单格底座最大18×20 B，相邻底座分别保留至少2 B横缝和3 B纵缝；三个实体不得合成一张跨格图。 |
| 单格无人机舱 | 本体贴图宽15 B，按有效裁切比例计算高度；底座18×20 B | 舱口、舱体和底座逐件对应；候选资源为独立单格舱，不能退回旧整舱图或数字角标。 |
| 车厢P四位 | 横向中心在车体中线±36 B，承力根部在±27 B；纵向两排相对载体中心-5/+62 B | 每件助推器17×19 B；中心位于74 B车体轮廓内。本体横向范围内缘±27.5 B、外缘±44.5 B，对车体边缘±37 B的覆盖约9.5 B，外伸约7.5 B。喷口朝下，喷流单件一条，不能以整块外置矩形板代替连接。 |

源图有效裁切框的宽高比应与显示宽高比相差不超过约12%，避免渲染时强行拉成短胖或细长。新短舱图有效轮廓约0.81，17/19≈0.895，差约9%；旧细长候选约0.45，和17/19差约100%，**判退而非缩放救图**。升级态与同类型装备须继续遵守对应接口的最大静态包络；如果功能必须超出，先提出新占位方案，不暗改容量规则或让武器遮车轮/车钩。

## 接入与验证

- 运行配置统一在 `station-prototype/configs/mount-layout.mjs` 的 `mountDisplayEnvelope`。载体、武器和喷流分别渲染；原画的透明边不计作可用设备尺寸。
- `platformArt=carV1` 现在自动进入同系列挂载试演，避免只开平台图却退回旧大舱；显式 `mountTrial=fit2` 仍兼容。没有这两个参数的默认入口保持原样。
- 新短舱使用内置 ImageGen 文生图，源文件 `美术设计/M21推进装置/助推器短舱蓝灰材质原创候选V2.png`（1150×1368透明PNG）。提示词核心：严格90度正俯视、接近方形的短厚蓝灰推进舱、一个朝车尾的宽喷口、深灰机械腔、小青色能量窗、铜灰喷口环、无底板/支架/火焰/文字。旧V1保留作比例失败对照，不覆盖。
- PASS：候选与默认各六组390装配、资源解码与页面错误；候选三舱资源路径、四件新短舱资源路径和17×19 B尺寸断言；真实游戏仅带`platformArt=carV1`出发后DOM检查为新舱1、旧舱0；390静帧及0.65秒冲刺截图目视。
- PASS：在新开的应用内验证页，直接打开三舱案例可见三张新单格舱图，点击四助推器可见四张V2短舱图；旧标签页仍可能保留改动前的模块实例，因此本轮把页面入口和相关显示模块版本推进到`mount-envelope2`，验收使用新开的页面，不能以旧标签页中仍在运行的页面实例判断资源未替换。
- 未验证：玩家主观认可、所有车厢混装与整段冲刺喷流净空、微信真机。测试节点数与坐标PASS不能替代视觉验收。

下一项：按玩家的实际装配观感决定是否正式采用V2短舱，再扩到其他武器类别；若P位包络仍不合适，先修接口布局和源图，不继续临时缩放。
