# 荒野列车模块契约规范

版本：1.0。适用于新增模块及遗留模块迁移，与 AGENTS.md、ARCHITECTURE.md 配套。本文规定契约写法和验收依据，不代表模块已实现或已通过测试。

## 1. 契约建立与维护

每个拥有独立业务状态、资源或公共能力的模块，在编码前建立 Docs/modules/模块名.md。纯内部辅助函数不单独建契约。实现或接口变化时同步更新契约，禁止只更新代码。

契约不新建架构规则；分层、依赖和 Owner 以 ARCHITECTURE.md 为准。新基础设施先检索已有实现。改变依赖边或资源归属时按 ADR 流程处理。

## 2. 必填内容

| 字段 | 必须说明 |
|---|---|
| 身份 | 名称、契约版本、所属层、源码公共入口、执行负责人或角色 |
| 范围 | 需求来源、职责、明确不负责的事项、验收条件 |
| 依赖 | 直接引用的模块和公共接口、注入方式、可选依赖缺失行为 |
| 公共 API | 输入输出类型、单位、前置条件、状态影响、错误码、重复调用语义 |
| 命令和事件 | 发布与订阅列表、字段、派发阶段、顺序、去重与取消方式 |
| 状态和资源 | 权威状态唯一 Owner、只读快照边界、借用或拥有的句柄、容量上限 |
| 生命周期 | 初始化、启动、停止、释放、重开和后台恢复行为 |
| 并发 | 执行线程、异步任务 Owner、取消、超时、异常和过期结果策略 |
| 配置和持久化 | 配置来源与校验、存档字段与版本、恢复和迁移失败行为 |
| 性能 | 调用频率、负载规模、时间与内存预算、测量环境和证据 |
| 验证 | 正常、拒绝、边界、生命周期、协作测试与完成证据 |

不适用项必须写明理由。未确定的性能预算写“待定义”，附确定预算的任务或里程碑；不得因此将性能检查记为 PASS。性能规范制定后按其设备档位填写，不照搬附件示例预算。

## 3. 接口和状态规则

- 公共入口仅导出最小必要接口；禁止其他模块引用 internal 文件、可变集合或平台句柄。
- 使用实体 ID 引用车厢、敌人和商品，不能用数组下标作为长期身份。返回快照不得允许调用者修改权威状态；声明快照版本或有效期。
- 输入在边界验证，包括数值范围、NaN、实体存活、runId、状态权限和配置引用。坐标、距离、时长、速度均标注单位。
- 可预期的业务拒绝返回稳定错误码，例如 INVALID_STATE、INSUFFICIENT_FUNDS、CAPACITY_FULL、STALE_RUN。编程错误或基础设施异常不能伪装成购买成功或静默吞掉。
- 有副作用的重复请求声明去重范围、保存时长和容量。重复 commandId 不重复扣款、伤害或发奖；超过保留期的旧请求按契约拒绝或交由上游保证，不默认再次执行。
- 多 Owner 操作必须指明事务协调方、提交顺序及失败恢复。购买遵循架构中的 Economy 事务约束，不能通过异步事件拼接半完成交易。

## 4. 事件和生命周期规则

事件表达已经完成的事实，例如 EnemyDefeated、PurchaseCommitted、JourneyPhaseChanged。声明唯一发布者与字段类型，必要时包含 eventId、runId、实体 ID 和代次。不得把未提交的意图当作成功事件。

派发遵循统一循环的结算阶段；监听器产生的新命令排到下一逻辑阶段，禁止重入结算。对顺序有要求时明确同一逻辑步内的排序依据，不能依赖未声明的订阅顺序。

默认生命周期为 created → initialized → running → stopped → disposed。重复 initialize/start 返回明确状态结果，不重复注册；stop/dispose 应可安全重复调用。是否允许 stopped 再 start 必须声明；disposed 后不再启动，重开使用新实例或新运行上下文。

停止时取消所属任务、注销订阅和输入，禁止继续产生业务副作用。释放时归还池对象、释放句柄；借用依赖由其 Owner 释放。测试需比较本模块的任务、监听和句柄计数是否回到预期基线。

异步结果必须校验运行 ID、模块代次及当前状态。取消后仍返回的结果应丢弃并释放资源。后台恢复只移除后台暂停原因，不能解除用户暂停或升级选择暂停。

## 6. 本项目示例要求

Journey 契约至少覆盖以下内容，具体 API 名称在实现任务中确定：

- 拥有行程阶段、段数与切换代次，输出只读速度和受伤策略；不拥有生命、镜头对象和钱包。
- 注入时钟、配置及事件接口，不引用 CameraPresenter 或平台 API，保持依赖无环。
- 从 Journey 进入 StationEntering 后停止新的战斗结算；只有匹配当前 runId 和切换代次的镜头完成通知可使其进入 Station。
- 镜头通知通过已声明命令边界进入统一循环，不由展示回调直接改写 Journey 内部字段。
- 同一完成通知重复到达只处理一次；过期通知拒绝；停止后到达的通知不开放商店。
- 高速阶段普通攻击不造成伤害；测试同时检查阶段策略和 Combat/实体 Owner 的实际应用结果，不能只检查提示文字。
- 验证后台暂停叠加、返回前台、死亡中止、重开与固定种子重放。

此示例是编写契约的要求，不是已完成模块或接口清单。

## 7. 验收与变更

契约、实现、配置和测试必须一致。记录执行命令、环境、测试数量与结果、性能证据位置。状态采用 PASS、FAIL、未验证、不适用；“不适用”必须解释。

必需项 FAIL 或缺少证据时，不标记模块已验收；允许交付小步进度并明确剩余项。旧原型的不符合项建立迁移任务，不通过改写契约来掩盖缺陷。

破坏性接口变化更新契约版本，列出调用方、迁移顺序、兼容处理和回退方式。普通内部重构也需确认对外语义与测试证据保持一致。
