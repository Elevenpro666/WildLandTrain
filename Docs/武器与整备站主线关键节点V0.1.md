# 武器与整备站主线关键节点 V0.1

日期：2026-10-25。状态：执行基线。

## 已锁定前提

- 最大编组为1个车头＋4节车厢。
- 车头Lv.1/Lv.2/Lv.3为2/4/6槽；车厢为4/6/8槽。
- 全部武器只使用统一20×20 B的T面接口；取消侧壁槽和助推器武器身份。
- 五个家族为机械切割、电磁传导、无人机作业、拒止与辐射地雷、镭射武器。
- “穿透”是镭射的一种攻击效果，不是武器家族名称。

## 关键节点

### K0｜载体与统一接口基线——已完成

V6车厢L1/L2/L3、4/6/8个可见T接口、现版共享轮组、整列连接、60 B轨距和紧凑连接间距已经接入浏览器版本。微信真机仍未验证。

### K1｜防御家族T面实装

1. K1A：单槽拒止器——已完成浏览器实装与相邻传导定稿。设备主体覆盖T接口并复用车头接口底座；基础设备只保护本节车厢，获得“相邻传导”后，连续相邻车厢都安装拒止器才会沿车厢边缘合并为跨厢力场，空缺车厢中断传导。地面敌人触界时真实推离；表现为内核涌能、边缘流动、双层拒止环和局部接触涟漪，不显示指向箭头、不造成伤害。普通商店暂不出售，试演数值不作为正式平衡。
2. K1B：单槽辐射地雷投射器。投射器、可数弹体、弹道、落点和持续伤害区分别可读；辐射不产生推拒。
3. K1C：两种构型同厢装配，分别占1槽；检查车轮、邻槽武器、连接区和屏幕可读性。

节点通过条件：站内占槽与出站实体一一对应；静态本体≤18×18 B；运行包络有登记；实际攻击结果和画面反馈一致。

### K2｜镭射武器家族实装

1. K2A：单槽基础镭射发射器与单条直线光束。
2. K2B：贯穿光路——聚束透镜→多层透镜，真实贯穿同一直线上的后续目标。
3. K2C：聚能发射——环式聚能→过载聚焦，强化同一条光束，不变成散射、追踪或爆炸。

节点通过条件：本体≤18×18 B；发射端与光束起点对齐；基础/贯穿/聚能三个阶段在手机竖屏上可区分；攻击判定和光束命中对象一致。

### K3｜前三个现役家族收口

- 机械切割：保留每厢最多1组、占同排2槽；完成最大往复包络登记。
- 电磁传导：补齐`arcCount`真实逐级分叉命中，不能只增加目标上限或装饰分叉。
- 无人机作业：复核双机、分区巡防、集中索敌和攻击反馈在统一T接口下保持可读。

节点通过条件：三个家族各4个节点都有对应本体部件或攻击反馈；站内装配、出站数量和升级状态一致。

### K4｜首批跨系融合

- 机械切割×拒止：拒止切割廊。
- 电磁传导×无人机：空中中继。
- 无人机×镭射：猎标镭射。

节点通过条件：融合只联动原有两件武器，不免费生成第三件实体；前置、目标选择、攻击结果和视觉反馈形成清楚因果。

### K5｜整备站美术与信息闭环

- 商店卡、占槽预览、已装武器、升级/融合状态和周转区统一使用五家族正式资源。
- 站内填满的接口，出站后必须显示对应数量和位置；不再引用助推器武器或旧侧壁资产。
- 车厢升级前后明确展示4/6/8接口增长。

### K6｜满编竖屏与完整流程验收

- 1个Lv.3车头＋4节Lv.3车厢在390×844浏览器中完成装配、出站、战斗、冲刺、升级、融合、进站和再次出发。
- 核对全列可见性、武器遮挡、特效层级、资源引用、暂停/恢复和清理。
- 浏览器证据与微信真机证据分别记录；没有真机证据时只标记浏览器PASS。

## 连续推进规则

- K1至K6按顺序推进；节点内部的小资源、代码、测试和文档更新不逐项请求确认。
