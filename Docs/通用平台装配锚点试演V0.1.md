# 通用平台装配锚点试演 V0.1

日期：2026-10-07。来源：用户三张390×844截图指出旧电弧过长、三级车厢无人机舱位于甲板中间、助推器没有对准P座。本试演只修**战斗画面安装表达**，不改变伤害、容量、购买、无人机数量或推进效果。默认画面保持旧装载；需同时传 `platformArt=carV1&mountTrial=fit2` 才启用候选底座和新挂载。

## 实际原因与锚点

原绘制坐标与新原画没有关联：电弧单件宽68 B、四件时使用四个侧缘外伸44 B横杆；无人机舱单件固定 `x=车体中心`；四助推器用车体中心 `y+20/+53 B`，而P座图像位于后半段约 `y+40 B`。因此先前“空载底座可见”不等于“装上设备合理”。

试演在 `station-prototype/configs/mount-layout.mjs` 固定可见四格中心：车头相对中心 `x±10 B`、`y-24/-5 B`；车厢 `x±10 B`、`y+13/+36 B`。P座以车厢 `x±24 B,y+40 B` 为受力根部，1/2件位于该纵向，3/4件以同座的上下短托架分开。位置是基于当前候选原画测量的**视觉锚点**，未成为正式游戏装配限制。

## 三类调整

| 问题 | 试演处理 | 390×844实画面判断 |
|---|---|---|
| 电弧长横杆 | 内置ImageGen以原单线圈电弧和车厢底座为参照生成单板紧凑模块 `美术设计/M18电弧挂载验证/电弧单板紧凑模块候选V1.png`，一个模块对应一块T；炮口朝车侧，投射线起点跟随对应模块 | 长横杆已消除，四件可数但每件蓝色能量结构过小，**单件识别仍需继续优化**；升级态外观尚未按此模块重做 |
| 无人机舱居中 | 不再把单舱锚在车体中心；单舱放后侧T板，三舱占三块不同T板，保留独立可数实体 | 三舱位置可区分，但舱体源图在小屏仍偏暗；舱门开合/飞行体关系未重验 |
| 助推器位置 | 1/2件对准两侧P座，3/4件沿同座的上下短托架分布；保留侧缘受力连接 | 静帧不再沿整辆车散布；喷流工作态和四件同时点火时的净空**未验证** |

紧凑电弧候选源图：1254×1254 RGBA，内容裁切约 `[196,264,984,712]`。生成提示核心：正俯视、单板占地、蓝灰旧化框架、一个青色能量核、铜线圈、仅朝右的短炮口；不得成为长横杆、不得烘焙闪电或背景。提示词要求三道铜圈，但输出在游戏尺寸下不能逐圈确认，不能据此宣称绕组数量达标。左右板在运行时镜像，仍保留同一件的识别。原电弧图与默认渲染不覆盖。

## 验证与待办

- PASS：默认和候选各六组390×844挂载页面的容量、可见件数、资源解码、短时推进、页面错误检查；标准网页客户端在开局、四电弧、三舱、四助推场景截图与状态读取；320/390完整远征默认回归。
- 目视结论：新布局比旧截图更符合底座/侧座；但紧凑电弧缩到20 B时能量核过小，不应标为正式美术PASS。
- 未验证：高级电弧升级结构、四助推喷流、极端混装、微信真机。下一轮先定紧凑电弧的基础/升级分级读感，再看喷流；任何会改现有合法装载数量的方案仍需单独确认。
