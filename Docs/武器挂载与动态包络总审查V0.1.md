# 武器挂载与动态包络总审查 V0.1

日期：2026-10-13。范围：`platformArt=carV1`、390×844、当前战斗画面单位 B。只核对共享装配坐标、静态占位和最大工作空间；不逐个新增混装试演，不改容量、伤害、攻击目标或资产。

## 结论

**尚不能确认全套装配与运行空间匹配规范，因此本轮不进入下一批美术资产。** T区尺寸关系成立；P区坐标和高等级切割轮动态包络存在几何冲突。已知数值足以判定失败，不以页面无报错或旧单组合试演通过替代。

## P区侧挂的二维净空边界

在现有车体与刀盘规则不变时，仅改变P挂点的平面坐标，无法同时满足“车体外缘安装、避开轮面、切割轮最高级全行程净空、相邻车厢净空”：

- 车体接口半宽37 B；若助推器宽17 B且需完全装在车体外缘，中心至少在±45.5 B。旋转短舱宽19 B时，中心至少±46.5 B。
- 切割轮中心横向全行程约47.5…67.5 B、半径22.5 B，扫掠X范围约25…90 B；侧缘助推器实体必与该横向范围相交。切割轮支架也在这条侧向区域内。
- 前后两排刀盘的扫掠Y合并约为-19.5…69.5 B；计入助推器半高8.5 B，刀盘中心相对任一助推器中心的禁入区约为(-28,78) B，长度106 B，大于车厢中心距85 B。因而只沿列车方向平移侧挂点，会在本车或相邻车厢再次进入刀盘包络。

**结论：当前是一项平面几何不相容，不是再微调几B就能解决。** 此前V1门禁只比较同一载体的局部包络，不足以证明整列车中切割轮与P设备互不冲突；V1不应被当成全车净空PASS。

## 产品约束：每厢空间玩法与推进器身份

各车厢都必须保留独立的装配空间玩法。因此，不能把尾厢集中推进直接当作“通用助推器”的默认落点，否则助推器将不再是每厢可装的P类装备。

- 若继续作为通用装备：每节车厢都保留本厢P装配可能性；需要为本厢助推器、轮组/车体边缘、切割轮扫掠区和邻厢净空找到可见且可判定的布局。二维侧挂目前不满足几何条件。
- 若集中到列车尾部：应命名和建模为“推进内核”一类列车级系统，而非P类通用装备；安装位置、占用空间、升级和容量规则需要单独定义，不能把其他车厢的空间或容量暗中借给它。

因此当前继续按“每厢可装的通用P装备”寻找方案；尾部推进内核只作为不同装备类别的备选设计，不替代原装备身份。

## 可行方向

1. 保持车体尺寸、车距与武器行程，给每厢P助推器和切割轮定义可见、可判定的不同高度层，并让几何校验与渲染层级共同表达；
2. 保持同一平面与全行程，但改变切割轮工作范围或装配边界，重新审查列车外形、连接结构和武器规则；
3. 单独立项设计列车级“推进内核”，明确它与各车厢P空间、容量和成长系统的关系。

优先探索方向1以保留每厢装配玩法并避免牵动车体尺寸、编组间距和切割轮既有升级表现；这会引入高度层装配规则，开始实现前需完成具体结构方案。方向2影响范围更大，不应仅为绕开冲突而暗自修改。方向3不是通用助推器的落位解。
