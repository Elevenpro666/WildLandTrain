# 荒野列车工程原则

版本：1.0。适用于新增与迁移代码，配合 AGENTS.md、ARCHITECTURE.md、MODULE_STANDARD.md 执行。本规范补充防止过度设计的决策规则，不替代架构、生命周期、性能和测试要求。

## 1. 实现前的选择顺序

先读取相关需求和代码，沿真实调用链确认问题，再按以下顺序选择最小可行方案：

1. 确认功能是否属于当前已授权需求；没有实际需求的扩展暂不实现。
2. 检查现有配置能否解决，避免为参数变化增加新系统。
3. 检索项目已有模块、工具和模式，优先复用或小范围扩展。
4. 评估标准库、目标平台能力及已安装依赖是否满足正确性、兼容性和性能要求。
5. 以上都不满足时，实现职责明确的最小新增代码。

平台能力必须通过既定适配层使用；复用不能制造反向依赖。不要为了少写几行绕过验证、事务或资源 Owner。已明确的产品要求不能以“简化”为由擅自删除。

## 2. 抽象与基础设施

- 每项新抽象必须对应当前的复用需求、测试隔离、平台差异或明确资源归属；不能只以“以后可能有用”为依据。
- 不预建未使用的插件系统、通用编辑器、多线程框架、全局管理器和空模块。
- 分层表示职责与依赖约束，不要求每次方法调用都逐层增加转发类。允许的直接依赖以架构矩阵为准。
- 少量相似代码可暂时保留；只有语义一致且共同变化时才提取公共实现，避免将不相关业务强行合并。
- 新增依赖先记录现有能力不足、引入收益、包体与运行代价、许可和替换方式。新增架构能力按 ADR 规则处理，普通内部实现不额外增加审批。

## 3. 最小改动与可读性

- 一个改动聚焦一个目标；不夹带无关格式化、重命名或重构。
- 代码行数和文件数量不是验收指标。不压缩成难以阅读的一行，不把战斗、渲染、商店重新塞进一个文件。
- 命名表达业务含义；公共 API 记录单位、前置条件和错误语义，内部注释重点解释原因与限制。
- 配置集中管理；配置项必须有实际使用方，不为尚不存在的玩法添加开关。
- 清理代码前检查调用方、资源引用和平台入口；删除用户资源或不可恢复数据仍需符合授权范围。

## 4. 修复根因与验证

- 区分表面症状与根因，检索受影响函数的调用方，在正确的公共位置修复，并验证关联路径。
- 非平凡逻辑保留能捕获实际故障的可运行检查；测试规模按风险决定，不设“只能一个测试”的限制。
- 优先复用现有测试设施，避免为一个小修复另建测试框架。
- 不能删掉输入校验、重复扣费保护、暂停恢复、事件注销、错误处理或存档保护来缩短实现。
- “没有报错”不等于正确；镜头看截图，交易看状态一致性，生命周期看释放，性能看指定设备上的测量证据。

## 5. 允许的阶段性简化

已知容量内的直接循环、简单数据结构和少量明确状态分支，可以优先于复杂框架。必须保持当前验收条件，并记录可测量的适用边界。

例如，少量敌人可先直接搜索目标；只有实测超出预算时才引入空间索引。不得仅凭算法名称宣称性能足够，也不能为省代码改变敌人行为或漏算命中。

对会产生实际技术债的简化，在相关代码附近及模块契约中记录：原因、支持规模、失效条件、升级路径、执行负责人或角色、复查里程碑。违反强制规范的简化仍按例外流程处理；注释不是豁免。

## 6. 本项目应用

| 场景 | 推荐处理 | 避免 |
|---|---|---|
| 调整车速与阶段时长 | 修改并验证行程配置 | 复制一套战斗循环 |
| 横向进站 | 现有镜头表现与行程状态协作 | 改写权威实体坐标来转镜头 |
| 新增武器 | 复用现有攻击契约，按真实差异扩展 | 每种武器自建计时器与伤害系统 |
| 商店按钮增加 | 复用购买命令和事务验证 | 按钮直接扣钱并改车厢集合 |
| 浏览器适配微信 | 实现必要平台端口 | 业务层散布平台判断 |
| 原型工程化 | 小步拆分并验证完整循环 | 一次性搭建未使用的大框架 |

## 7. 交付检查

每次交付确认：目标必要、复用已检查、改动聚焦、架构未越界、必要保护未减少、验证与风险匹配。发现多余复杂度时先说明具体成本，再简化，不能凭代码长度判断质量。

按 AGENTS.md 记录真实完成状态与剩余项。未实施的检查或未采集的性能证据标为“未验证”；不宣称本规范已由 CI 自动执行。

## 8. 参考与取舍

参考用户提供的《AI Agent 游戏开发工程规范与模板》及已查阅的 [Ponytail 项目规则](https://github.com/DietrichGebert/ponytail/blob/main/AGENTS.md)。采用其理解问题、优先复用、减少无关代码和保留必要保护的思路；不采用将最少文件、最短代码或单个测试作为硬性目标的做法。

本文件为项目适配后的独立规范，不安装 Ponytail 插件，不覆盖项目入口规则，也不将第三方基准成绩视为本项目的性能承诺。
