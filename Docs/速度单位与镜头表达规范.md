# 速度单位与镜头表达规范

版本：V1.3，2026-10-06。状态：**常速120、默认冲刺500 SU/s、3.2 SU/米和无敌结束边界已确认；1.2 秒减速曲线及镜头取景仍需持续体验检查。** 适用于竖屏战斗镜头。本文优先于 `Docs/modules/场景距离映射.md` 内的历史速度记录。

2026-10-06 默认档变更：用户审看 500 SU/s 后明确决定“默认用500这档”。因此默认出站与手动冲刺均为 500 SU/s（156.25 玩法米/秒），基础300米冲刺持续1.92秒；仍用1.2秒减速、末端解除无敌，首轮无敌约3.12秒。默认出站普通蝎子随后按用户要求改为26只、纵向约900 SU的非等距散布，基本覆盖冲刺全过程；原300 SU/s／10只保留为可配置历史对照，不再是默认。

## 1. 单位与已确认数值

| 名称 | 单位 | 含义 | 当前决定 |
|---|---|---|---|
| 场景单位 SU | 逻辑世界长度 | 战斗视图坐标中的距离；不是设备物理像素，缩放屏幕不改变 SU | 战斗运动与镜头沟通的标准单位 |
| 场景速度 | SU/s | 每秒经过的场景单位，由同一模拟时钟积分 | 常速 **120 SU/s**；默认冲刺 **500 SU/s**，出站第一帧即冲刺速度 |
| 场景位移 | SU | 速度随时间积分的结果 | 列车、地表、轨道、障碍、敌人使用同一世界位移基准 |
| 冲刺距离与路线距离 | 当前界面标“米” | 玩家看到的可冲刺距离和路线进度，不是速度的默认单位 | 保持 **3.2 SU/米**；常速 37.5 玩法米/秒，冲刺 156.25 玩法米/秒；品质一 300 米冲刺持续 1.92 秒。距离仍按车头品质＋助推器决定 |
| 时长 | s | 模拟时钟秒数 | 暂停、选卡时不推进；无敌、镜头与场景共享此时钟 |

今后讨论速度默认写 SU/s；说“米/秒”时必须明确是玩法距离单位与真实秒数的比值，不能把 `300 SU/s` 自动解释成 `300 米/秒`。390×844 的 SVG 视图只是当前逻辑画布；320 宽设备按视图缩放，不另造一套速度数值。

## 2. 世界运动与镜头边界

- `Game/Journey` 拥有权威列车速度状态和距离；`CameraPresenter` 只读状态决定取景，不得靠另一套私有速度改变战斗时间、无敌或敌人追击。
- 世界行进 `W(t)=∫v_world(t)dt`，单位 SU。镜头位置 `C(t)` 同为 SU。列车和敌人的屏幕坐标由各自世界坐标与同一个 `C(t)` 推导；地表、铁轨、树石和地面投影必须共享镜头映射，不允许各自滚动。
- 出站开场没有准备／起步加速：战斗第一帧进入冲刺状态，默认速度为 500 SU/s。车头从下方越过护栏与怪群；镜头何时开始追随由取景目标决定，但不得造成地表倒流、实体穿越或规则/画面速度相反。
- 冲刺距离用尽后进入明确的减速状态，速度连续、单调趋向 120 SU/s。**减速全程仍无敌，到达常速状态后才解除无敌**。当前试演候选为 1.2 秒三次平滑速度曲线；这段额外位移不消耗已用尽的冲刺距离，结束后才开始充能。时长和取景仍待体验审核。
- 镜头回中是镜头追上减速列车产生的相对运动，不单独把车身拉回、瞬移或叠加第二次位移。镜头速度不得倒退；列车、背景、撞飞怪的前后关系保持一致。
- “高速冲顶所需时间”由屏幕内实际距离、500 SU/s 与镜头跟随量共同决定。先按真实场景速度表现，不额外加速车身或缩短路程；冲顶后镜头再跟随，减速时追上并让列车回中。早先对300 SU/s估计的2.3～2.7秒冲顶时长属于历史对照。

## 3. 当前代码与目标的冲突（接入门禁）

| 项目 | 当前 `station-prototype` 实现 | 规范目标／待确认 |
|---|---|---|
| 规则常速 | 已接入 37.5 米/秒 | 按 3.2 SU/米对应 120 SU/s |
| 规则冲刺 | 已接入 156.25 玩法米/秒 | 对应默认500 SU/s，首帧即满速 |
| 场景速度 | 已接入常速120、默认冲刺500 SU/s | 战斗路程与地面位移使用同一个 `sceneTravel` 积分 |
| 距离换算 | 保留 `sceneUnitsPerMetre=3.2` | 用户已确认，不另设表现层倍率 |
| 冲刺结束 | 已接入 `sprinting→decelerating→charging` | 1.2 秒减速试演期间无敌、到常速才充能；候选曲线待审核 |
| 出站冲顶 | 已接入按500 SU/s提前追随的取景 | 旧300 SU/s与0.8秒冲顶方案均为历史对照；以实际画面验收 |

旧 `rear-flight1` 为历史对照，不再作为速度标准。新浏览器候选已接入，但微信真机与体验审核未完成。

## 4. 修改与验收门禁

1. 任何速度提案必须同时写出：原值/新值、单位、适用状态、距离换算、持续时间、无敌边界、镜头取景和对敌人/障碍的影响。含糊的“300速度”“更快”先问清单位。
2. 与已确认的常速120／默认冲刺500 SU/s、首帧高速或此前认可的视觉目标冲突时，列出冲突和代价，先请用户确认，不以历史代码值或助手猜测覆盖。
3. 改动先保持单一权威速度源，再更新规则积分、场景位移与镜头；不得只改 HUD 数字或单独移动列车图片。
4. 验收在 390/320 宽检查首帧、过栏、冲顶、减速和回中；量测 SU/s 与位移连续性，并回归暂停、二次冲刺、无敌/受伤、怪物追击、撞飞、完整站点往返。浏览器 PASS 不等于微信真机 PASS。

## 5. 待用户确认的最小决策

1. **距离换算已确认**：现有 `3.2 SU/米` 为唯一映射；120／500 SU/s 分别对应玩法距离37.5／156.25米/秒，品质一300米冲刺持续1.92秒。
2. **已确认出站默认速度**：500 SU/s，从第一帧真实经过场景；300 SU/s仅作历史对照。
3. **已确认无敌边界，曲线待试演审核**：无敌覆盖高速冲刺和完整减速阶段，进入 120 SU/s 常速状态才解除。浏览器已接入 1.2 秒候选；时长并非最终产品常量，需用户体验后确认。
